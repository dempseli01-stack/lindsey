# Cursor competitor differentiation — challenge frames only

For the interview challenge, competitive framing is limited to **two** competitors:

1. GitHub Copilot  
2. Claude Code  

Do not train or present other named competitors (Windsurf, Codex, JetBrains AI, Amazon Q, etc.).

---

## 1. Cursor vs GitHub Copilot

GitHub Copilot is often understood as helping developers write code faster.  
Cursor is positioned more as an AI-native environment for completing broader tasks across a codebase.

**Useful themes:**
- from snippet help to task completion
- from local suggestions to broader codebase context
- from isolated assistance to workflow support
- from point solution to more integrated development experience

---

## 2. Cursor vs Claude Code

Anthropic’s Claude Code has come up most frequently in recent conversations.

We do **not** need to argue that Claude Code is weak, and our edge is usually **not** that Cursor has exclusive access to better intelligence. It’s that it **applies intelligence more effectively** across real engineering workflows.

**Useful themes:**
- model neutrality instead of single-provider dependence
- stronger integration points across the SDLC through tools like Bugbot
- better support for large, complex codebases
- faster time to value across a broader team
- a more complete environment for planning, writing, reviewing, and iterating

---

## 3. How this maps to Cursor positioning

Sell what buyers feel: **workflow · context · execution**.

Four differentiators (lead with one based on pain):
1. Model neutrality
2. Large codebase / harness performance
3. Faster time to value
4. Platform across the SDLC (Bugbot, Agent Review, Automations)

Enterprise posture (not a competitor frame): Privacy Mode / ZDR, SSO / SCIM / audit, admin controls — so AI coding can be standardized without ungoverned sprawl.
